# 2. Planning

## Purpose

Turn the six product areas into a build order that a single client can finish, and name what is deliberately left for later.

## Release cut

The first release in this repository is a demonstration client. It includes every area from the product description as a working screen, backed by one coherent record. It excludes live connectors, accounts for more than one student, push notifications, and a surveyed map.

| In this build | Later |
| --- | --- |
| Five tabs: Heute, Studium, Chat, Campus, Mehr | A real SIAM OpenID Connect login on a backend |
| Degree progress for a 180 ECTS plan | The legal Prüfungsordnung, per program, from the university |
| Deadlines, news, lecturers, tutorials, rooms | Sync jobs against C@MPUS, ILIAS, and SDG Campus |
| Local assistant plus an optional Grok server | Tool use against live course forums |
| Notes, import, export, peer sharing on device | Moderated multi-user sharing |
| Topic index for past exams | Any redistribution of exam files |
| German and English | Further languages |

## Sequence inside the build

1. Fix the record: program areas, modules, grades, sessions, rooms, deadlines. If this is wrong, every screen and every answer is wrong.
2. Put pure functions on top of it: totals, average, locks, next-semester suggestion, local answers.
3. Lock those functions with `tools/assistant/check-assistant.ts` before the UI depends on them.
4. Build the shell: sign-in, tabs, device storage.
5. Build the screens in the same order a student meets them: today, study, module, chat, campus, documents, peers.
6. Add the server last, so the app is useful when the server is absent.

## Effort and shape

One Expo SDK 57 app, TypeScript, Expo Router, no custom native projects checked in. iOS and Android projects are generated by prebuild when a binary is needed. A dependency-free Node server sits beside the app so the API key never enters the bundle.

The demonstration student is in the 5th semester with 90 ECTS passed and 18 in progress, 30 ECTS behind a 30-per-semester pace. That gap is intentional. A student who is perfectly on pace makes the requirements screen and the assistant boring.

## Risks carried out of planning

| Risk | Plan |
| --- | --- |
| The UI implies the grades are the signed-in user's | The home screen names Lena Hartmann and the word Demonstration. Credit answers cite the demonstration record |
| Grok invents a deadline | The model receives a fact sheet and is told to use only that. The local answer remains if the call fails |
| A PDF import promises full-text AI and then shows nothing | Binary PDFs are listed, and the reader says there is no text layer yet |
| Scope grows into a backend | Connectors stay as timestamps and copy until a separate project owns the server contract |

## Exit check

Planning is complete when the backlog separates "in this build" from "later", and the build order starts with the record rather than the screens. See [delivery/backlog.md](../delivery/backlog.md).
