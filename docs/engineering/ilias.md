# ILIAS connector

ILIAS at Universität Stuttgart (`https://ilias3.uni-stuttgart.de`) has no
student JSON API. The app therefore reads the same HTML pages a browser
renders. The page reads run in a hidden WebView on the device; the assistant
server parses and caches what the app harvested, so server load does not grow
with the number of active users.

## Code layout

`server/ilias.mjs` is the stable public barrel. The implementation is split by
concern in `server/ilias/`:

| File | Responsibility |
| --- | --- |
| `constants.mjs` | Base URLs, client id, user agent, headers, cache TTL and page cap |
| `errors.mjs` | `iliasError(status, code, detail)` |
| `cookies.mjs` | `CookieJar`, `Set-Cookie` parsing, cookie normalization |
| `util.mjs` | URL resolution, login-name normalization, masking, URL safety and kind helpers |
| `markup.mjs` | Entity decoding, visible text, tag attributes, login-page detection |
| `login.mjs` | Standard-form parsing, rejection text, identity, form login |
| `dashboard.mjs` | Dashboard block parser |
| `content.mjs` | Course/group/folder material parser and members-tab link |
| `members.mjs` | Members-tab parser |
| `profile.mjs` | Public-profile parser |
| `reads.mjs` | Live page, profile, image, and file reads with a cookie |
| `cache.mjs` | Ingest, parsed-row cache, freshness metadata |
| `session.mjs` | Per-user cookie registry, connect/disconnect, session-backed reads |

Routes, the admin console, the terminal probe, and tests keep importing
`server/ilias.mjs`, so the split is internal.

## Login

The standard form lives at:

```
https://ilias3.uni-stuttgart.de/ilias.php?baseClass=ilstartupgui&cmd=post&fallbackCmd=doStandardAuthentication
```

The field names are generated by ILIAS (`login_form/input_3/input_4` for the
login name, `…_5` for the password), so `parseIliasLoginForm()` reads them from
the page instead of hard-coding numbers. The form is `multipart/form-data`; the
server posts the hidden fields plus those two values once.

ILIAS shares the university password with C@MPUS, but the login name is the
mail address before the `@`: `st206509@stud.uni-stuttgart.de` becomes
`st206509`. `iliasLoginName()` normalizes both API input and the terminal probe.
The app prefills the login name from the session and, when the opt-in C@MPUS
credential is in the device vault, offers to reuse it directly.

A successful login answers `302` with a `PHPSESSID` cookie and redirects to:

```
https://ilias3.uni-stuttgart.de/ilias.php?baseClass=ilDashboardGUI&cmd=jumpToSelectedItems
```

The password is used once, in that login request. The resulting `PHPSESSID` is
kept in a per-account `Map` in `server/ilias.mjs` (it disappears on restart),
and the login response also hands it to the authenticated app. The app seeds
the cookie into its own WebView cookie store (`CookieManager`, WebKit store on
iOS) and performs every later page read there. The server no longer fetches the
dashboard or course pages for a normal app read.

An expired session is detected when a harvested page contains
`name="login_form"`. The client first re-seeds the WebView from
`GET /v1/ilias/session` and retries once; if it is still a login page, the read
maps to `401 ilias_session_expired` and the app asks to reconnect.

## Cache

Every page the app reads is posted to `POST /v1/ilias/ingest` as HTML. The
server parses it, stores the parsed rows, and keeps the raw HTML so a parser
change can replay a page without asking the device to fetch it again.

| Table | Content |
| --- | --- |
| `user_ilias_snapshot` | Last parsed dashboard per account |
| `user_ilias_content` | Parsed course/group/folder pages, keyed by account, ref id, kind |
| `user_ilias_members` | Parsed members tabs for courses and groups, keyed by account, ref id, kind |
| `user_ilias_profiles` | Parsed public member profiles, keyed by account and target user id |
| `user_ilias_pages` | Raw harvested HTML, keyed by account and page |
| `user_ilias` | Source marker and account name |

Cached reads are served for 15 minutes (`ILIAS_CACHE_TTL_MS`). A response
carries `cached` and `stale`; the app refreshes a stale or missing page in its
WebView and ingests the result before rendering it. Content rows are pruned to
the newest 500 pages per account, raw pages likewise.

The cache is per account, not global: course visibility is authorization-
sensitive, so one student's page is never served to another.

The web build has no injectable WebView. It keeps using the server-side live
read (`?live=1` on the dashboard and content routes) as a fallback; mobile
builds never take that path.

## Dashboard blocks

`parseIliasDashboard()` slices the dashboard by block id:

| Block prefix | Content |
| --- | --- |
| `block_dash_mem` | Courses and groups, grouped by semester or course |
| `block_pdnews` | News items with `news_id` |
| `block_pdmail` | ILIAS mailbox rows with `mail_id` |
| `block_pdtasks` | Open to-dos |
| `block_pdcal` | Mini calendar (not parsed line by line) |

Each item keeps its title, absolute ILIAS URL, type (`Kurs`, `Gruppe`, …),
reference/news/mail id, group heading, description, and property pairs such as
`Datum` or `Lernfortschritt`. The parser is deliberately tolerant: a missing
block yields an empty list instead of failing the page.

## Members

Courses and groups link to a members tab (`ilUsersGalleryGUI`). That link
carries an object-specific `cmdNode`, which no other page reveals, so
`parseIliasContent()` returns it as `membersUrl` and the app reads exactly that
URL. The members page is parsed by `parseIliasMembers()`:

- Each member is an `il-card thumbnail`; the display name sits in `card-title`
  and the login name in the `Anmeldename` definition list.
- A `Zuständigkeit` value marks the group's contact person. That row is
  returned as the tutor and sorted to the top.
- ILIAS renders `Nicht freigegeben` when a user has not published a profile.
  The login name is then the only identifier, so the parser spaces its camel
  case (`AnaMariaTonu` becomes “Ana Maria Tonu”) and still lists the member.
- Course galleries expose no roles at all. A course therefore lists every
  member without a tutor/participant badge instead of guessing.

Members and profiles are cached like content and pruned to the newest 500 tabs
and profiles per account. Pull-to-refresh on the app screen re-reads both the
material and member pages.

Tapping a member opens the public profile ILIAS offers for that row
(`ilPublicUserProfileGUI`). `parseIliasProfile()` reads that page:

- the rendered name (`ilProfileName`, e.g. “Herr Fabian Bross”), the h1 form
  with the login (`Bross, Fabian [FabianBross]`), and the course context;
- the profile image (`ilProfileImage`), which is streamed through the
  assistant server because `deliver.php` needs the ILIAS cookie;
- every published `ilProfileSection` (institution, contact, and anything else
  the user enabled), with prose and links;
- the e-mail, the ILIAS-mail link, the vCard link, and any course/group links
  a section carries.

Profiles are cached per target user id, so the same person is not re-read from
a second course. Members without a public profile have no profile link; their
detail screen shows the login name and a note that the profile is not public.
ILIAS public profiles do not, by default, list a user's other courses; the
screen shows the current course as context and renders any course links the
profile itself exposes.

## Server routes

| Route | Auth | Behavior |
| --- | --- | --- |
| `GET /v1/ilias/config` | optional | Does this server have an `.env` session, and is this account connected? |
| `GET /v1/ilias/session` | app | Hands the current `PHPSESSID` back so the app can seed its WebView |
| `POST /v1/ilias/session` | app | `{ account, password }`, `{ cookie }`, or `{ env: true }`; signs in once and returns the dashboard plus the cookie |
| `POST /v1/ilias/ingest` | app | `{ page: 'dashboard' \| 'content' \| 'members' \| 'profile', html, url, refId?, kind?, userId?, fetchedAt? }`; parses and stores a harvested page |
| `GET /v1/ilias/dashboard` | app | Serves the stored dashboard (`cached`, `stale`); `?live=1` is the web fallback |
| `GET /v1/ilias/content` | app | Serves one stored course/group/folder page; `?live=1` is the web fallback |
| `GET /v1/ilias/members` | app | Serves one stored members tab; with `?live=1` the app passes the members link from the content page as `?url=` |
| `GET /v1/ilias/profile` | app | Serves one stored public profile by `?userId=`; with `?live=1` the profile link is passed as `?url=` |
| `GET /v1/ilias/image` | app | Streams a profile image with the account's cookie; `?url=` must point at ILIAS and return `image/*` |
| `POST /v1/ilias/session/expired` | app | The WebView saw a login page: drops only the in-memory cookie so the vault can reconnect |
| `DELETE /v1/ilias/session` | app | Forgets the in-memory cookie, clears the WebView cookie, demotes the platform link |
| `GET /v1/ilias/file` | app | Streams one repository file with its ILIAS content type and filename |
| `GET /v1/ilias/viewer` | app | Fetches one PPTX or DOCX and returns a self-contained viewer page |

The password is only a request-body field. It is not written to the database,
not logged, and not echoed. The `PHPSESSID` is returned only to the
authenticated app that just signed in, or on the authenticated `GET
/v1/ilias/session` call, because the device now owns the page reads. The
cookie is never written to logs or to the database.

The operator can set `ILIAS_SESSION_COOKIE` and `ILIAS_ACCOUNT` in `.env` and
then connect with `{ "env": true }`. That cookie is only used for an account
that was explicitly connected through the env source.

## Terminal probe

```bash
npm run ilias:login -- --probe
npm run ilias:login -- --user st206509 --password-stdin
npm run ilias:login -- --cookie "$ILIAS_SESSION_COOKIE"
```

`--probe` prints the public form field names and needs no credentials.
`--password-stdin` keeps the secret out of the shell history. `--json` prints
counts and the first rows; it never prints the password or the cookie.

## App

The **ILIAS** tab connects automatically from the signed-in C@MPUS session and
never shows a manual login. While the session is restored it shows a loading
state; afterwards it renders a search bar and grouped rows for courses, groups,
news, mail, and to-dos, with categories and account actions in a left drawer.
Pull-to-refresh re-reads the dashboard. Demonstration and local profiles have no
university identity, so they get an explained "not connected" state instead of
an endless loader. If a real session cannot be restored from the vault, that
state names the reason and offers a retry; a biometric vault is only unlocked by
that explicit action, never in the background.

Page reads share one hidden WebView (`IliasHeadlessProvider`, mounted at the
app root). The provider registers a `fetch` bridge; `src/ilias/api.ts` asks the
server for the cache first, and on a miss or stale entry injects a same-origin
`fetch` into the hidden page, posts the HTML to `/v1/ilias/ingest`, and renders
the parsed response. Requests are serialized through one queue.

The app session is revalidated on every resume (`SessionRefresh`); the ILIAS tab
follows the same beat. It awaits the shared session probe, reloads the cached
dashboard, and — when the opt-in C@MPUS credential sits in the device vault —
reconnects a session that a server restart dropped, without asking for the
password again.

A course or group row opens its content page in the app (`/ilias/<refId>`).
Folders and categories in that list drill down into the same screen. When the
object has a members tab, the screen lists its tutor and members below the
materials, with the member count in the section heading. Tapping a member opens
`/ilias/mitglied`: avatar, profile sections, e-mail and ILIAS-mail actions, and
any course links the profile publishes. A PDF, PPTX, or DOCX row opens the
reader at `/ilias/datei`. PDFs are fetched through `/v1/ilias/file`, written to
the cache, and rendered with `react-native-pdf` (PDFKit on iOS, PdfRenderer on
Android); the web build hands a blob URL to the browser's own PDF viewer in an
iframe. Presentations and documents take the same file screen but render
through `/v1/ilias/viewer`: the server fetches the file, inlines the
`pptx-preview` or `docx-preview` browser bundle and the file bytes into one HTML
page, and the app shows that page in a WebView (web: an iframe with the fetched
page). Every Word page is stretched to the viewport width; images and tables are
capped at that width, and headers and footers stay inside the page card instead
of the clipped page margin. The content scrolls; the file never reaches a
third-party viewer. Other file types keep the share sheet, and every file still
has "Open in browser" and "Share" actions.

`react-native-pdf` and `react-native-blob-util` carry native code, so the
development build has to be rebuilt after a fresh install. The config plugins
in `app.json` add the Android blob provider and the PDF packaging options.

## Admin

`#/ilias` lists every account with a stored snapshot or live session, the
source, session state, parsed counts, and the last read. `#/users/<id>/ilias`
shows the stored dashboard, browses the live content page of a course or group,
lists that object's members tab, and opens a member's public profile with the
same avatar and sections; it can also disconnect the session. The overview adds
an `ILIAS` health chip and a live-session KPI.

## Limits

The app reads the dashboard, the object lists of courses, groups, folders, and
categories, and the members tabs of courses and groups; the server only parses
and stores those pages. Course member galleries do not expose roles, so only
group contact persons are marked as tutors. It does not paginate the magazine,
post to forums, or send mail. PDFs, PPTX, and DOCX render in the app; other
formats are downloaded or shared, not previewed. File bytes still stream through
`GET /v1/ilias/file` on the server (they are not harvested by the WebView) —
presentations and documents go through `GET /v1/ilias/viewer` — and are cached
only for the current read, not kept as an offline library. Those
pages would need their own parsers and a separate permission decision.
